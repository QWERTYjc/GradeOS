# Pi 教师工作区

首次使用从“准备材料 → 开始批改 → 查看结果”进入。材料未上传前突出三类上传入口；上传后展示原页画布、直接开始按钮和底部轻量输入框。材料、答卷划分、任务记录和审阅按需展开。教师可直接提问、安排分批任务，或在批改中补充说明。

## 启动

在 `experiments/pi-grading` 执行：

```sh
npm ci --ignore-scripts
npm run dev
```

打开 <http://127.0.0.1:4173>。默认使用 `本仓库 .venv/bin/python` 的 Pillow，以及 PATH 中的 Poppler `pdfinfo`、`pdftoppm`。可在启动进程的环境中设置 `PI_WORKSPACE_PYTHON` 为另一个已安装 Pillow 的 Python。

无需模型即可上传、划分答卷、圈注、编辑文档、手动保存任务和查看既有结果。要启用自然语言安排与任务执行，使用已有、获准使用的 OpenRouter 凭据文件：

```sh
npm run dev -- --env /absolute/path/to/ignored.env --cap 2
```

该文件需提供 `OPENROUTER_API_KEY`；不要把凭据放入前端。支持 `--model openai/gpt-6.1-terra`（默认）或 `openai/gpt-6.1-sol`。自然语言安排每次准入预算为 $0.50，每次执行的准入预算由 `--cap` 控制，默认 $2，最大 $5；这些是实验的保守准入估算，不是供应商强制账单上限。费用缺少回执时保留未知状态。

单个工作区默认保存在本实验目录的 `.workspace/`，已忽略入 Git。用 `--data /absolute/path/to/another-workspace --port 4174` 打开另一份独立工作区。每个目录只启动一个服务进程。

## 教师操作

### 三类材料与自适应批改

材料入口分别接受 **Marking scheme、题目、学生答卷**。前两项可选；学生答卷是批改对象。
每个任务默认就是批改，不再要求填写“想做什么”或选择任务类型。独立选择题目和 MS 后，
新批改统一用一个“补充批改要求”输入框填写学科、年级、考试体系或反馈偏好；留空即可继续。
材料与答卷范围合并为可展开的摘要；执行方式、联网和结果处理收在“更多设置”。
旧任务单独保存的学科信息会保留，并可在“更多设置”中编辑。
点击“开始批改”会保存本次设置并启动，无需先保存再寻找启动入口。“保存草稿”仍可单独使用。
若启动失败，界面保留已创建的草稿，重试沿用同一批次；未连接模型时可保存草稿。
题目和 MS 的空选项统一显示“无”。有就使用，没有就按现有材料批改；不因未上传题目而
要求补传、补全或触发联网搜索，也不单独设置材料补全流程。
上传题目不会增加学生人数或混入答卷划分。旧工作区会补齐空的题目列表。

主 Pi 阅读材料后，通过 `review_grading_requirements` 判断补充要求是否适用。适用要求直接采用，
无需额外确认；遇到与题目、MS、考试规则冲突、影响公平评分、含义不明确或无法执行的要求，
会说明具体问题、提出调整建议并等待老师回复。自动继续模式同样要等待这个回复。
回复后主 Pi 再判断是否解决；未解决可以继续追问。已核对的要求进入评分实施文档与子 Agent 上下文。
原始要求、问题、回复和最终采用版本分别保留；无补充要求时不增加这个确认步骤。
这一机制接入 MS 原路径和自适应路径；语义判断由主 Pi 完成，执行门禁阻止未经核对的要求进入批改。
2026-11-16 补充要求更新验证：228 项 Node 离线测试通过，覆盖空要求、直接采用、冲突追问、
回复后重新判断、未解决时继续追问、撤销要求和分值依据更新。浏览器验证了空白保存及补充内容持久化，
控制台无错误。Pi 工具循环使用离线模型响应；尚未验证真实模型对要求适用性的判断质量。

| 本批材料 | 执行方式 |
| --- | --- |
| 题目 + MS + 答卷 | 主 Pi 先读完整题目与 MS，理解题意、独立核对解答，再保存逐题评分依据。 |
| 题目 + 答卷 | 主 Pi 推导参考解答与评分条件，标为建议标准；没有可靠分值依据时仅提供定性反馈。 |
| MS + 答卷 | 保留现有 evidence-v4 路径；指定额外考试要求或允许联网时采用自适应路径。 |
| 仅答卷 | 按答卷现有内容批改；卷内题干完整且有分值时，主 Pi 推导建议评分条件并给分。无可靠满分时提供定性反馈，具体无法判断的项目保留待定，其余继续。 |

自适应路径先加载明确的批改方法（定量推导、写作、证据论证），再整理分批候选条目。
这些方法是审查步骤，不是对某个考试体系的认证，也不自带该考试的分数段、扣分或给分规则。
考试体系不能确定时保留未知。主 Pi 在后续模型回合核对候选，冻结来源哈希与规则后生成
《评分实施.md》，沿用“先确认再批改 / 自动继续”的既有批次授权。
随后为每份答卷启动新的 Pi Agent，只开放该份原卷和选定题目/MS，逐项保存判断及证据。
标准冻结后不再根据学生得分修改；失败学生不自动重试。

逐题结果明确区分“用户提供的 MS / 根据题目推导 / 依据本份答卷内容”。
推导评分始终标为建议并要求复核，即使实施说明已确认，也不会被重命名为官方标准。
完整题意和原卷满分足以推导建议评分条件，不因缺少 MS 一律改为定性反馈。共享总分的小问作为一个评分单元处理，不编造各小问满分。具体疑点单独列为“待核实”；一般的建议标准身份与具体疑点分开。无题意、无可靠满分或材料冲突时，仅对应项目给定性反馈或保留待定；未知分值不是零分。
题目覆盖不完整或任何一项未定时，整卷总分与满分都保持空值；已判定小计单独标明。
老师可确认定性反馈而不赋分；无法确定的项目保留待定，原记录保留。

**可选检索**：服务环境提供 `BRAVE_SEARCH_API_KEY`，并在该批任务勾选“允许联网查阅参考资料”后启用。
实现依据 [Brave Web Search 官方接口](https://api-dashboard.search.brave.com/app/documentation/web-search)。
主 Pi 只应用公开考试/学科/题目检索词，不发送学生身份、私有答题文本或老师私密备注；这一语义限制由提示约束，不能视为完整的自动脱敏保证。
每批最多 6 次搜索和 8 次网页读取，保留 URL、时间、正文哈希与实际引用。
仅搜索摘要不能成为评分依据；需要读取正文并核对考试、版本和题目匹配关系。
网页不会变成用户上传的官方 MS，网页来源也不能单独创造分值依据。
网络未配置、调用失败、需要登录或无法读出正文时保留信息缺口。
网页读取限公开 HTTPS 文本，固定解析后的公网地址，不跟随重定向；PDF 来源需上传原件。
检索供应商费用独立于现有模型预算，当前未实现合并美元计费上限。

该路径位于 `src/workspace/adaptive-{contract,agents,runtime}.mjs`，研究工具在
`src/workspace/grading-research.mjs`。运行目录保存 `adaptive-run.json`、每次候选、
`grading-plan.json`、`plan-review.json`、各答卷原始结果和 `summary.json`。
原有命令行 cohort 契约不变；这里是 PI 本地工作区中的新实验路径，尚未接入生产批改接口。


### 画布与任务操作

1. **上传与划分**：底部 `+` 或右上角“材料”可上传 PDF、PNG、JPEG。材料抽屉保留均分、按文件分卷、从页前分卷、合并、排序、改名和撤销。明确取消全部勾选后，Agent 范围为“仅评分标准”，不会自动扩大到所有答卷。
2. **画布与注释**：默认阅读，用套索自由画一圈或框选，松手后只保留选区，点击选区才显示注释气泡。可同时保存多处注释，点击标记继续编辑，右上角小叉移除单处；“添加到对话”才会将引用带入输入框。区域保存原页哈希、页码、归一化坐标和实际手绘路径。Pi 可通过工具读取原图对应裁剪，刷新或缩放不会改变来源含义。
3. **开始批改**：上传答卷后，画布上方直接显示“开始批改”；题目、MS、补充要求可以留空。确认界面中可展开调整范围和更多设置，主按钮直接保存并启动本批。需要稍后继续时可保存草稿。输入框仍可直接提问，也可让 Pi 拟定最多六批任务。
4. **过程与补充**：默认只显示一行当前活动；展开记录可查看真实工具动作、保存进度与已结算费用。显示的是动作及结果，不展示隐藏推理。批改中可暂停后续模型请求、继续、停止，或选定当前任务补充说明。已经发出的请求可能仍会完成；新说明排队到后续上下文，不会改写已保存成绩。
5. **问题与审阅**：Agent 的 `ask_teacher` 会保存具体问题和原页引用，等待老师回答；其他独立答卷可继续。老师可圈选原文后回复。主 Agent 在原对话核对 MS 后仍有未决问题时，进入教师确认点。最终评分审阅以独立、追加的记录保存，原始评分保留；待定项目不能被静默记为零。
6. **并排阅览**：“并排打开”最多摆放四个窗口，每个窗口独立切换文件、翻页和缩放；同一 MS 可同时显示不同页。布局在本浏览器保留，手机可横向切换窗口。
7. **直接编辑**：文档默认显示排版后的正文，文件标题栏的“编辑”可直接修改；历史版本和导出收在同一栏的更多菜单中。支持 Markdown、TXT、CSV、JSON 和 Agent 文本报告。编辑自动保存；其他窗口或 Agent 同时修改时保留本地草稿并提示合并。选中文字会浮出“添加注释 / 添加到对话”，引用绑定当时版本与原文。
8. **评分实施与批改授权**：主流程为“准备材料 → 开始批改 → 查看结果”。开始任务先核对 MS，通过 `publish_marking_guide` 输出 `评分实施.md`。默认“先确认再批改”：老师可以直接编辑，或在输入框与 Agent 讨论并修改这份文档；保存不会启动批改，必须点击“确认并批改”才分派答卷。Agent 仍在调整文档时不能确认。开始批改时可在“更多设置”选择“自动继续批改”，由这一批次的授权采用生成的版本并继续；来源疑点仍会询问老师。已开始的批次保持原授权。

采用版本的正文、哈希、版本号及采用方式进入各答卷的上下文，并写入运行目录。后续编辑保留为新版本，不改变已采用批次；新批次沿用老师最新的说明，并按该批自己的授权决定是否等待确认。实施说明用于落实原 MS 的条件，不能绕过原文和固定分值上限。多个批次的同名说明在文件选择器中标明批次，避免混淆。

**仅 MS 且无额外考试要求或检索的整卷批改**调用现有 `run-cohort.mjs`，采用 Luna 中等思考档，每份答卷一次请求；批注和汇总由脚本生成。完整答卷像素保留，页外增加行列标尺；macOS 下使用本地 Vision 的文字候选和行位置，候选不具有评分权威。工作区运行额外启用 `--interaction-dir`，将任务要求及后续说明按答卷和来源范围传给 Pi。它仍按完整冻结标准批改；自然语言不能绕过原文、改变固定分值上限或只批某题。修改评分政策需要修订来源并另建任务。

**自由任务**使用真正的上游 Pi Agent，读取选定原页及已有结果，生成带来源引用的文档，例如漏页疑点清单、错因整理或讲评建议。它不直接更改分数。实际能力由材料读取、结果读取、保存文档等工具提供，不具备 shell、任意网络或成绩发布工具。

## 答卷评分批注与费用

已保存的评分点自动出现在对应答卷页边。每点展开后包含得分、学生证据、MS 条件、原始判定、老师复核及本批采用的评分实施 MD 版本；缺少证据或分数会明确保留待确认。正文由脚本投影已有评分记录，不启动模型，也不重新存一套分数。页边标记默认收起，支持按批次切换、只看疑点、隐藏，以及从批注进入 MS 对照、评分审阅或添加到对话。

固定 MS 的新批改任务在同一次严格结构化 `submit_grading` 输出中附带位置。模型按题项与评分点键提交证据、分数和理由，以及 `i3.C12:F15` 这样的页码行列引用；脚本无损转成已有评分记录和原页坐标。多处证据可引用多个范围。标尺放在原图外，不遮盖或改动原卷笔迹。展示时可保留一格附近笔迹，原始范围仍单独保存；这不等于自动补齐遗漏证据。无作答证据与未能定位分开记录，不因缺少位置而把学生记作零分。

macOS 本地文字识别没有远程 OCR 或第二次模型请求；识别文本仍会增加 Luna 输入费用。没有自动定位重试或额外模型汇总。实际测试仍发现原卷符号误读和评分分歧，坐标有效不代表给分正确；结果需要结合原页和评分实施文档审阅。确认后的 MD 正文和来源标准哈希在每份答卷中保持一致。

旧批次和自适应任务仍可按已有页码显示批注。老师明确需要补定位时，可在对话中要求“把第 6 页的评分批注定位到对应笔迹”：`read_annotation_points` 只读该页编号与证据，`read_pages` 提供原图，`place_grading_annotations` 只写位置。这条按需路径会额外计费；新批改已保存的坐标直接复用。

坐标与原记录哈希、原页哈希、答卷和批次绑定，来源变化即失效。教师圈注与自动评分批注分开保留；点击自动批注才突出显示定位区域，重叠区域优先响应教师圈注。批注覆盖已有评分点，不等于重新检查或发现评分记录之外的每一处问题。

## 数据与执行边界

- 上传原文件与页面哈希保留；划分必须覆盖全部答卷页，每页只能属于一份答卷。单文件不超过 40 MB / 300 页，单工作区不超过 1,500 页。
- 开始任务时冻结材料、顺序和学生范围。之后更改划分会使旧草稿需要重新确认范围，不会改变已运行任务的输入。同一答卷不能同时启动两个批改任务。
- 未选中的答卷不能被 Agent 读取或添加到任务草稿。评分标准可作为任务材料选用。
- 来源引用必须来自 Pi 已实际接收的工具结果；同一模型回合中先请求读取、再假定读过并保存的引用不被接受。
- 模型输入与输出沿用实验回执记录；原图以哈希记录到审计文本。任务成果、批改产物与复核草稿持久化。停止或服务重启不会自动触发付费重跑。
- 交互问题、回复、补充说明和公开动作保存在每次运行的 `interaction/`。备注仅在实际请求上下文包含相应标记时记录送达；等待老师或暂停的时间不计入交互运行的执行时限，费用和请求数限制仍生效。
- 原有 MS 路径的主 Agent 核对沿用整理历史，但不接收学生答卷、学生问题或无 MS 来源范围的说明。自适应路径在有题目/MS时同样先隔离答卷；仅答卷模式为恢复题意而逐份读取，不能将学生答案当作正确答案。学生工作单元只能读取自身答卷与 MS；圈选文件哈希和坐标在服务端验证。
- 文档、修订历史和注释保存在工作区；注释移除为归档，原始图像和原始报告保留。旧文字引用绑定旧版本，不会漂移到改写后的段落。实施文档不授权捏造原 MS 规则或超出固定分值；有冲突时需要老师澄清并保留待定。
- 不指定 `--interaction-dir` 的命令行批改保留原有模型工具和输入。已有旧版工作区进程可以继续使用原界面；重启该工作区服务后切换到画布界面，避免静态文件更新打断其他正在运行的批改。
- 服务仅监听 `127.0.0.1`，对 Host、Origin、Fetch Metadata 和写请求 token 校验。它是单机实验入口，没有生产账号、班级权限或发布成绩能力，不应通过反向代理直接暴露给公网。

这是独立的 Node ESM 浏览器入口，不改主 `frontend/` Next.js 应用，不需要另加构建工具或运行主前端的构建。标准控件图标复用 Ant Design 的 MIT 资源，许可证位于 `web/assets/icons/LICENSE`；GradeOS 字标沿用主前端现有的文本字标形式。


### 推导标准的独立校核

完整题意与卷内满分允许建议数值评分。主 agent 必须转录完整题干；prepare_grading_plan 在采用标准前自动执行：

1. 新的隔离上下文只接收题干白名单，不接收学生答案、候选解答、评分条件、教师补充或主 agent 对话。
2. 独立校核上下文对照原题，检查候选答案与隔离推导，使用代回、逆操作、另一条推导或反例等具体检查。可使用有限精确算术工具，不执行代码或访问网络/文件。
3. 已确认的内容保持原样；任何修正必须保留说明。校核绑定到候选 hash，不能给修改后的标准复用旧校核。
4. 仍未确定的标准只阻止对应项目给分，其他项目继续。批改 agent 如果发现标准与原题矛盾，也必须保留该项待定及具体说明。

隔离针对上下文和输入字段；题干仍由读过原卷的主 agent 转录，原页校核负责发现遗漏或混入学生答案的情况。此机制不能保证所有推导正确；以实跑证据评估，不以总分吻合替代逐项验证。相关校核及算式结果与原始评分分别持久化。
