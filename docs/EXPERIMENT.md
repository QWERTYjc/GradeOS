# Pi grading experiment

Isolated grading experiments using the **actual upstream Pi Agent class**.
The original `run.mjs` grades one paper directly. `run-cohort.mjs --scripted` prepares or reuses
a verified MS, waits for the implementation document approval, then dispatches one Luna call per
student from host code. Reports and annotation overlays are generated by scripts.
See [the cohort design and entrypoint](../COHORT.md). Neither calls GradeOS grading, GradeOCR,
LangGraph or Codex for inference. Reference scores and historical grading outputs are evaluator-only
inputs after the result is frozen.

The cohort entrypoint `npm run grade:cohort -- ...` uses Luna at medium reasoning,
strict named point decisions, short ordinary full-credit reasons and locations in the same response.
After the teacher approves the MS implementation, each answer book gets one grading request.
All answer pages are included. With a verified frozen rubric and exact approved guide, only original
MS pages needed for general instructions, visual dependencies and unresolved source details are
reattached; the complete compiled criteria and approved Markdown remain unchanged. Use
`--all-ms-images` to attach every original MS page.

`--annotation-grid` puts column/row rulers outside the original image; original pixels remain
identical. Luna returns short references such as `i3.C12:F15`; scripts convert them to source-page
rectangles. Disjoint evidence can have multiple ranges. `absent` and `unlocated` are distinct.
The viewer can show the original range or one cell of surrounding ink. This display padding does
not establish that the model selected every necessary piece of evidence.

The preset additionally uses optional macOS Vision (`--local-ocr`) for local text candidates and
source-bound line locations. It makes no remote OCR request, does not correct the student's algebra,
and has no score authority. Its text still consumes Luna input tokens. The CLI preset requires
macOS/Xcode command-line tools; on another platform invoke `run-cohort.mjs` directly without
`--local-ocr`. The workspace enables it on macOS only; the image-only path is not the same measured
A/B configuration.

There is no automatic second grading, correction, locator, feedback or reporting call. Invalid or
truncated output remains a failed run with its receipt. Positive exception proposals and dependent
awards remain pending teacher review. Unchanged source validators do not prove that Luna read
handwritten symbols correctly: the real-paper evaluation still found transcription and scoring
errors, and these results are review drafts, not a qualified automatic grading release.
`annotations.html` shows original answer pages, scoring criteria, evidence and reasons without
another model call. Adaptive grading without a fixed MS remains a separate existing workflow.

For a frozen replay, supply `--rubric /absolute/rubric.json` and optionally
`--approved-guide /absolute/marking-guide.json`. Both must match their original sources; an approved
guide is replayed verbatim and hash checked. Live workspace approval remains required with
`--interaction-dir`. For the no-annotation comparison, invoke the CLI directly and omit both
`--annotation-grid` and `--inline-annotations`, retaining the same OCR and reasoning settings.
The measured difference includes rulers, location hints and output references, not just output
coordinate tokens. `--cold-cache-namespace` separates comparison prefixes; actual cache reads and
costs must still be checked in provider receipts.

The older model-orchestrated workflow remains available by omitting `--scripted` in a direct CLI
invocation. The following reporting options describe that older workflow.
The all-non-full source review experiment is opt-in and is not enabled by this preset.
See [the current cohort selection](COHORT.md#当前选用luna-单次批改脚本批注).

`--lean-reports` (with `--economy-reporting`) writes personal summaries and substantive comments
for lost, unknown, disputed or exceptional credit. Only ordinary full-credit items with explicit
point attestations can use labeled fixed commentary; the complete original point table is always
rendered. The model may still add a review concern for those items. When all students have written
their results, the coordinator receives the first bounded result batch and GradeOS analytics
directly in the dispatch response. It must consume this evidence before submitting; further
batches still require source-bound notes. No grades or required source-image checks are removed.

This harness installs only `pi-agent-core` and `pi-ai`; it does not load coding-agent skills,
extensions, repository instructions or Codex's skill catalog into grading requests. Runtime
cost comes from the explicit prompts, tool schemas, images and model output.

The candidate `--model google/gemini-4-hydrogen` uses the same Pi/OpenRouter implementation,
with explicit metadata in `src/experiment-models.mjs` because Pi 1.5.2's bundled catalog does
not contain it. The route is Google's standard `google-vertex/global` endpoint, low reasoning,
no fallbacks and no transport retries. Public capabilities and endpoint prices were checked on
2026-11-15; run artifacts preserve the actual model, route, wire and provider cost receipts.
This is an experimental model selection, not general grading qualification. Reusing a frozen
MS tests downstream grading and reports; it does not re-evaluate MS compilation with the new model.

## Minimal host responsibilities

`prepare.py` renders both original PDFs with Poppler and hashes every page. The agent has two tools:
`read_pages` and `submit_grading`. The latter validates page delivery, unique item identities,
bounded numeric awards and source references, sums item scores, and freezes the result before
ending the upstream loop. The model still determines rubric semantics, coverage of subparts,
evidence ownership and awards; syntactic checks do not establish semantic correctness.

Every provider request has a reservation, immutable payload receipt (image hashes instead of
base64), terminal usage, and a preserved assistant response. Missing billed cost remains unknown
and retains its reservation. Pi and its OpenAI SDK have zero automatic network retries; OpenRouter
is restricted to the `openai` endpoint group with fallback disabled. Provider-internal execution
cannot be inferred solely from client POST count.

A normal stop before submission permits at most two recorded continuations. Errors, truncation,
aborts and exhausted limits end as incomplete. No reference-driven retry or best-of-N selection.
No image/history pruning or summarization is enabled in this first experiment.

## Run

Requires Node >=22.19, Python 3, and Poppler `pdftoppm`. Use a new output directory per run.

```sh
npm ci --ignore-scripts
npm test
../../backend/.venv/bin/python -m unittest discover -s test -p 'test_*.py'
python3 prepare.py --scheme /absolute/path/scheme.pdf --student /absolute/path/student.pdf \
  --output /absolute/path/prepared --long-side 1400
node src/run.mjs --input /absolute/path/prepared --output /absolute/path/preflight
# Paid execution; only with an authorized existing OpenRouter credential file:
node src/run.mjs --input /absolute/path/prepared --output /absolute/path/run-1 \
  --env /absolute/path/ignored.env --model openai/gpt-6.1-terra --cap 1 --execute
```

The run manifest is written before inference: one run, low reasoning, 12,000 maximum output
tokens per request, 24-request maximum, 15-minute deadline, request concurrency one.
The dollar cap is a conservative admission estimate (UTF-8 bytes + 4,096 tokens per image),
not a provider-enforced billing ceiling. It rejects the long-context price tier. This estimate
is specific to the admitted Terra/Sol models and image dimensions; qualify changes separately.

After termination, a separate evaluator accepts a reference JSON with `items` containing
`item_id`, `score` and `max_score`. It never supplies these to the grader:

```sh
python3 evaluate.py --run /absolute/path/run-1 --reference /absolute/path/private-reference.json
```

The successful harness state is `submitted`, not a claim that every source subpart is covered.
Only the separate evaluation can establish reference-item coverage and fixture agreement.

## First execution, 2026-11-14

Six JavaScript checks and two evaluator checks passed. They exercise the actual Pi loop and
adapter with synthetic responses, including one local HTTP 500 proving no client retry.
The first live Terra attempt was rejected by OpenRouter with HTTP 403:
`This model is not available in your region.` No page image was sent and no grade was produced.
One call was admitted; no usage/cost receipt was received. USD 0.063327 remains an unknown-cost
reservation, not spending. The result does not establish a Pi cost or grading-quality advantage.
The post-audit source changes were made after this failed run and are not represented as tested
inference behavior. There was no automatic model/provider change or additional paid run.

## Third execution, 2026-11-14

After the user explicitly requested another retry, the same Terra configuration succeeded:
two model responses, 33.36 seconds of model/tool execution, all 49 page images delivered,
34 scored items, 78/100. Posthoc evaluation found 31/34 item matches against official labels,
9/12 question matches and absolute item error 4: M2 fixture regression fail.
Provider receipts total USD 0.11214325, with no unknown cost in this attempt, no client retries
and no completion continuations. The two earlier 403 attempts retain unknown costs.
The model requested every page in its first turn and submitted in its second turn.
This is one observed completion, not a matched harness A/B or production qualification.

## Interpretation

Compare all score-detail items after freezing, including missing/extra IDs and unresolved awards.
Report raw model awards separately from host arithmetic and any future human review.
Historical Codex figures are API-equivalent estimates, while OpenRouter may report billed cost.
The earlier Codex runs used different prompts, endpoints and image sizes, so they are exploratory
references, not a controlled harness A/B. A smaller harness does not by itself prove lower cost,
better grading, stability, generalization or production readiness.

`--lean-reports` now uses `source-bound-v5`. The feedback model selects actual point references,
practice actions and review concerns; the host renders score facts and preserves full MS conditions,
source text and related context. Required commentary covers every non-ordinary item, while
`additional_items` preserves optional concerns on ordinary full-credit items. The cohort model
likewise selects evidence and actions: personal free-form summaries are not forwarded into its
context. Report tools reject free-form mathematical solutions, causal diagnoses and score summaries.
Original grading reasons remain clearly labeled audit records; this contract does not verify their
mathematics or the source MS, and deliberately offers narrower practice guidance rather than new
worked solutions. No extra report-review model call is added.

The exact per-student tool schema is frozen in `feedback-*/input-contract.json`. Only the feedback
phase requires its terminal submission tool; grading retains on-demand source/answer tools. Pi
validation diagnostics omit the duplicate rejected argument echo from subsequent model context,
while full original messages remain in transcripts. Rejected brief reasons can be corrected through
a submission-hash-bound reason-only tool; awards, evidence, relations and review flags remain
unchanged, and the whole original validation runs again. This changes submission reliability,
not score authority or image recognition.

While a reason amendment is pending, the same agent sends a small request-only checkpoint:
complete affected and related MS items, their exact proposed point records, general instructions,
review/source notes, relevant bound pages and subsequent tool turns. It keeps all original-page
tools. The original transcript and complete pending submission stay intact; reopening grading
restores them automatically. Ambiguous source/identity/page bindings or extra interactive context
retain the full input. This adds no agent, model stage, dependency or background summarizer.
