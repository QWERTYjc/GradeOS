# Pi 批改结果画布

本轮基于 GradeOS 已有的原卷画布、文档阅读器、批注与底部输入框，改善批改结果的发现和审阅。产品仍使用现有本地 Node 服务与静态前端。

## 阅读顺序

1. 已有批改记录的工作区在没有运行中任务或草稿时直接打开结果。
2. 顶部选择批次和答卷；原卷批注、个人报告、汇总报告可直接切换。
3. 原卷视图左侧按题浏览，可筛选失分和待定项。题目内部以评分点切换。
4. 原卷占据主要画布，右侧展示该评分点的理由、答卷证据、来源与复核入口。已验证的证据区域决定定位位置；没有区域时只打开所引用页面。
5. 复核草稿在切题和面板收起时保留在当前页面；保存后仍保留原始评分。所有必需复核项解决后可完成本批审阅。
6. “就此问 Pi”把当前评分点明确放入输入框的引用区，并限定到对应答卷。
7. 阅读报告时使用已有报告目录，避免同时显示两套题目导航。

## 视觉和交互

- 沿用浅灰工作区、白色原卷、紧凑工具栏和底部输入框。
- 桌面依据面板参与布局，不遮挡原卷；窄屏使用可收起面板和按需目录。
- 题目选择、批注选中与面板展开使用轻量过渡。证据定位平滑滚动，遵循减少动态效果偏好。
- 失分、待定、定性反馈各有文字状态，信息不只依赖颜色。

## 数据边界

- 题目分值只是本批已保存评分点的展示。未知分值保持待定，定性反馈不转为数字。
- 中断、取消、失败和运行中批次明确显示“仅显示已保存结果”。
- 展示复核结果需要匹配任务、记录和原始哈希。
- 原卷跳转复用既有来源校验；重分卷或来源变化后不把旧记录定位到其他答卷。
- 本轮没有改变模型、评分流程或报告正文，没有新增付费推理调用。
- 复核草稿目前在当前页面内保留；刷新页面前仍需保存。原生安装包与独立官网不在本轮改动范围内。

## 验证

在已有结果的隔离副本中，通过真实浏览器验证：直接进入结果、按题/评分点切换、失分筛选、上一题/下一题、原卷与 MS 来源跳转、复核草稿保留、保存复核、报告切换、评分点引用、390px 目录与面板。

已有数学报告的章节目录和公式阅读仍可用；只有报告的工作区不再被提示必须上传学生答卷。截图和工作区副本留在忽略的 `runs/` 中，不随代码提交。

`npm ci --ignore-scripts`、`uv sync --locked`、`npm run check` 通过。新增离线测试覆盖分值状态、跨批次复核隔离、部分结果标记、来源归属、审阅完成条件与静态资源可达性。浏览器检查没有当前预览的 error/warn 日志，390px 根页面没有横向溢出。未运行真实模型批改，未验证新的评分准确率或原生桌面安装包。
